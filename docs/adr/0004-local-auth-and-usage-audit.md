# ADR-0004: 使用本地账号、签名会话与结构化使用审计

## Status
Accepted

## Context
当前工具需要在企业微信 SSO 接入前支持账号密码登录，并让超级管理员查看每个成员的访问次数、停留时间、费用评估次数、导出次数、估算消耗金额和访问时间。统计页和统计 API 必须由服务端鉴权，不能只依赖前端隐藏。

## Decision
继续使用模块化单体架构和现有 SQLAlchemy 数据库。账号密码使用 scrypt 加盐哈希；登录后发放 HMAC-SHA256 签名、HttpOnly、SameSite=Lax 的短期会话 Cookie。新增账号、访问会话、使用事件、查询上下文和按日聚合表。超级管理员统计页 `/admin/usage` 及其 API 使用服务端角色校验。开发环境从 `.env` 中的超级管理员用户名和密码哈希初始化账号，源码和 `.env.example` 不保存真实密码。

访问统计使用页面打开时创建访问会话、30 秒心跳和离开时 `sendBeacon` 收尾；费用评估和导出在服务端成功受理时记录事件。实际消耗金额以签名费用凭证中绑定的估算金额计入已提交导出，不信任浏览器传入金额。

## Consequences

### Positive
- 无需引入外部身份服务即可交付当前版本。
- 服务端 RBAC 能保护隐藏统计页和统计数据。
- 审计数据与业务任务关联，金额不可被客户端篡改。

### Negative
- 本地账号方案不含找回密码、MFA 和企业统一身份生命周期。
- 单机内存登录限流不适合多实例部署。

### Neutral
- 接入企业微信 SSO 后可保留使用审计表，仅替换身份来源。

## Alternatives Considered
- 仅使用前端隐藏页面：无法阻止普通成员直接调用统计 API，拒绝。
- 立即接入企业微信 SSO：当前缺少企业应用参数，暂缓。
- 引入完整 OAuth/身份平台：当前内部 MVP 复杂度过高，暂缓。

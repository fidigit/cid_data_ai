# v0.0.2 Reference UI Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use executing-plans to implement this plan task-by-task.

**Goal:** 将查询首页改造成与用户选定效果图高度一致的三步查询工作台，同时保留现有费用评估、ODPS 查询、XLSX 导出、登录和统计能力。

**Architecture:** 后端 API 和数据模型保持不变。首页继续使用原生 HTML/CSS/JavaScript，仅重组页面结构、增加三步状态映射，并把额度限制从模态弹窗改为卡片内联反馈。日期范围组件继续复用现有单框组件。

**Tech Stack:** FastAPI、原生 HTML/CSS/JavaScript、自定义 date-range-picker。

---

### Task 1: 重建首页视觉层级

**Files:**
- Modify: `app/web/index.html`

1. 建立顶部品牌区和系统状态胶囊。
2. 建立“输入查询、确认费用、导出数据”三步进度条。
3. 将查询文本、日期范围、帮助信息和主操作集中到单个工作流卡片。
4. 保留费用回执、执行日志、查询结果和 PV/UV 区域，但按当前阶段渐进显示。
5. 增加最近查询列表，数据仅保存在当前浏览器，不伪造后台记录。

### Task 2: 统一交互与错误反馈

**Files:**
- Modify: `app/web/index.html`

1. 增加 `input / cost / export / complete` 阶段状态映射。
2. 费用评估通过后突出导出按钮；输入变化后回到第一步。
3. 删除每日额度模态弹窗，429 错误显示在页面内联结果区域。
4. 保留登录全屏页和日期范围选择器，不新增弹窗组件。

### Task 3: 版本与验证

**Files:**
- Modify: `pyproject.toml`
- Modify: `app/main.py`
- Modify: `README.md`

1. 将版本号更新为 `0.0.2`，但不创建 Git 标签、不提交、不推送。
2. 运行 `node scripts/check_frontend.cjs`。
3. 运行 `.venv/Scripts/python.exe -m pytest -q`。
4. 在浏览器验证登录页、查询页、日期选择、费用失败内联状态和响应式布局。

### Acceptance Criteria

- 桌面端的构图、暗色网格、绿色强调、字号层级和三步流程与参考图高度一致。
- 页面不出现额度模态弹窗或新增的浮动小窗。
- 费用评估、导出门禁、错误信息、下载和 PV/UV 功能保持可用。
- 1280px、1024px 和移动端宽度均无横向溢出或组件重叠。
- 所有自动化测试通过，GitHub 远程仓库保持不变。

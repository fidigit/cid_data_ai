# v0.0.6 Implementation Plan

**Goal:** Add selected-value condition groups, multi-event queries, and new/old user filtering without replacing the existing UI.

**Architecture:** Validate structured filters on the server and render one canonical SQL plan for estimation and execution. Preserve the legacy primary event column; store requested event lists in an additive context column and actual event codes on aggregation rows. Existing accounts, usage, and artifacts remain untouched.

**Tech Stack:** FastAPI, Pydantic, SQLAlchemy, MaxCompute SQL, XlsxWriter, vanilla JavaScript/SVG.

1. Domain/SQL: add condition models (12 operators, BIGINT bounds, AND/OR groups), new-user selection, space-delimited events. Test validation, injection strings, numeric source safety, parentheses and client/WEB separation.
2. Persistence/API: additive migration for event lists and aggregate event identifiers; keep legacy fallbacks. Bind all filters/events to the cost fingerprint; test old database preservation and token tampering.
3. Worker/XLSX: aggregate by date and actual event before detail LIMIT; compute missing requested events using client substring or WEB exact matching. Include event identity, conditions and coverage notes in first worksheet.
4. UI: preserve dark mint styling; selected-only funnel dialogs with two default rows, add/remove, internal AND/OR; global group connector and readable summaries. Insert new/old selector between version and fields. Preserve spaces. Group bars by day, switch PV/UV and event selection, show missing/empty states.
5. Verification: isolated SQLite pytest suite, frontend syntax check, mocked browser desktop/mobile interactions and screenshots. Do not run paid ODPS queries or upload to GitHub.

Confirmed: scenario 2 uses value1 = 100 OR value1 = 200 (the value2 < 200 sample was a typo). Different field groups support a single AND/OR connector, with explicit parentheses. Text targets use literal matching; numeric targets must be valid signed 64-bit integers. NULL/noninteger/out-of-range source values do not match numeric predicates. At least one new/old option is required.

SQL reference: [MaxCompute CAST / CASE documentation](https://www.alibabacloud.com/help/zh/maxcompute/other-functions) and [string functions](https://www.alibabacloud.com/help/en/maxcompute/string-functions). The source cast is applied outside a guarded CASE so invalid numeric data is converted to NULL, not an exception; text literals use CHR for quotes/backslashes/control characters.
